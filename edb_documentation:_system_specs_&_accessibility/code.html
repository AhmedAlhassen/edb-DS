The technical core of the EDB Design System. This section details the tokens, compliance standards, and contribution workflows for developers.

accessibility_new

Accessibility Checklist (WCAG 2.1 AA)

Focus-visible States

Critical

All interactive elements must have a high-contrast focus ring (min 2px width) that is visible via keyboard navigation.

Aria-labels for Banking Actions

Required

Buttons with icons only (e.g., Delete, Edit, Transfer) must include descriptive aria-labels for screen readers.

Color Contrast Compliance

Required

Text and functional UI elements must maintain a minimum contrast ratio of 4.5:1 (AA standard).

animation

Motion Guidelines

Reduced Motion Support

For EDB accessibility, all transitions must respect the prefers-reduced-motion media query. Non-essential animations should be disabled for users with vestibular sensitivities.

Contribution Rules

1

Branch Naming

Use feat/component-name or fix/issue-description naming conventions.

2

Theme Parity

Every new component must be tested in both Light and Dark modes. RTL support is mandatory for Arabic localization.

3

Documentation First

Update the MDX documentation and add the component to the Storybook directory before opening a PR.
